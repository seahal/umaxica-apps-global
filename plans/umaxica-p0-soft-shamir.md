# P0 Fixed Contracts — Soft Shamir

Codename: Soft Shamir. Each contract below is a "share" in the trust chain: change any one of them
and a RP, browser, native app, or external service breaks in ways that are hard to reverse. This
plan catalogs all P0 (immutable) and P1 (important, often missed) contracts, maps each to its
current implementation, identifies open gaps, and defines guardrails.

---

## Context

Umaxica has three RP-facing surfaces (app / org / com) with Acme as the sole OIDC OP/AS and Sign as
the credential gateway. Several URL/domain contracts are load-bearing across system boundaries: RPs
cache discovery documents, browsers bind `__Host-` cookies to a specific host, passkeys are bound to
the RP ID at registration time, and external services register endpoint URLs in their own
dashboards. None of these can be renamed as a routine routing cleanup.

This plan was opened to formally identify those contracts, surface implementation gaps against
advertised behavior, and establish the guardrails that prevent accidental breakage during future
refactors.

## P0 Fixed Contracts

### 1. OIDC Discovery / JWKS

These paths are advertised in the discovery document. RPs fetch and cache them. Any rename
invalidates cached discovery documents and breaks RP interop for the cache TTL.

| Path                                | Controller                                                | Status         |
| ----------------------------------- | --------------------------------------------------------- | -------------- |
| `/.well-known/openid-configuration` | `Acme::{App\|Com\|Org}::WellKnown::DiscoveriesController` | ✅ implemented |
| `/.well-known/jwks.json`            | `Acme::{App\|Com\|Org}::WellKnown::JwksController`        | ✅ implemented |

Issuer URL is constructed by `OidcIssuer` from `Rails.configuration.x.boot_config` hosts
(`app/services/oidc_issuer.rb`). Discovery content is generated by
`OidcDiscoveryDocument.for_resource_type` (`app/services/oidc_discovery_document.rb`).

**Guardrail**: `test/integration/routes/oidc_discovery_route_stability_test.rb` bridges the
discovery document content with actual Rails route resolution — any rename that desynchronises the
two will fail CI before a RP notices. Added as part of this plan.

### 2. OAuth / OIDC Token Endpoints

These paths are advertised in the discovery document.

| Path               | Controller                                               | Status          |
| ------------------ | -------------------------------------------------------- | --------------- |
| `/oauth/authorize` | `Acme::{App\|Com\|Org}::Oauth::AuthorizationsController` | ✅ implemented  |
| `/oauth/token`     | `Acme::{App\|Com\|Org}::Oauth::TokensController`         | ✅ implemented  |
| `/oauth/userinfo`  | `Acme::{App\|Com\|Org}::Oauth::UserinfosController`      | ✅ implemented  |
| `/oauth/revoke`    | `Acme::{App\|Com\|Org}::Oauth::RevocationsController`    | ✅ implemented  |
| `/oidc/logout`     | `sign_oidc_logout` concern (Acme-wired)                  | ⚠️ gap — see §3 |

PKCE S256 is enforced at `OidcAuthorizeRequestValidator`; `redirect_uri` is exact-match only
(`OidcRedirectUriValidator` — `Array(client.redirect_uris).include?(uri)`).

### 3. OIDC Logout (end_session_endpoint) — **Resolved**

The discovery document advertises `end_session_endpoint = {issuer}/oidc/logout`. The implementation
at `app/controllers/concerns/sign_oidc_logout.rb` + `app/services/oidc_end_session_request.rb` now
handles:

- GET and POST (`show` / `create` in `SignOidcLogout`)
- `id_token_hint` verification via `SecurityJwtOidcIdTokenCodec` (lazy client-id scan)
- `post_logout_redirect_uri` validated exact-match against
  `OidcClientRegistry.valid_post_logout_redirect_uri?`
- `state` forwarded to the post-logout redirect
- `ui_locales` threaded through
- `post_logout_redirect_uris` registered per client in `OidcClientStoresStaticClientStore`

The gaps identified in `plans/grill-me-implementation-ready-refactored-lerdorf.md` are resolved. The
route contract tests in `test/integration/routes/acme_route_contract_test.rb` pin GET+POST for all
three surfaces.

**Remaining**: verify end-to-end with a third-party RP client to confirm interop now that
spec-alignment is in place. Track in `plans/grill-me-implementation-ready-refactored-lerdorf.md`
Slice F/G.

### 4. OAuth / OIDC Redirect URIs

Registered in `OidcClientStoresStaticClientStore`
(`app/services/oidc_client_stores_static_client_store.rb`). These are **immutable** once a client
registers; rename requires coordinated client-side update.

| Client           | Redirect URI                                    | Auth method        |
| ---------------- | ----------------------------------------------- | ------------------ |
| `sign-rp`        | `{SIGN_SERVICE_URL}/oidc/callback` (3 surfaces) | `private_key_jwt`  |
| `base-rails-rp`  | `{SIGN_SERVICE_URL}/oidc/callback` (3 surfaces) | `private_key_jwt`  |
| `core-next-rp`   | `{CORE_SERVICE_URL}/oidc/callback`              | `private_key_jwt`  |
| `app-ios-rp`     | `umaxica://oidc/callback`                       | `none` (PKCE only) |
| `app-android-rp` | `com.umaxica.app:/oidc/callback`                | `none` (PKCE only) |

Social auth callbacks are equally fixed (registered with OmniAuth and referenced from external
provider dashboards):

| Path                      | Provider          | HTTP method |
| ------------------------- | ----------------- | ----------- |
| `/social/google/callback` | OmniAuth Google   | GET         |
| `/social/apple/callback`  | OmniAuth Apple    | POST        |
| `/social/failure`         | OmniAuth fallback | GET         |

State validation: `SocialAuthCallbackStateStore` — 5 min TTL, single-use, `secure_compare`. Origin
allowlist: surface-specific host list in `SocialCallbackGuard`.

**Gaps (from `plans/backlog/social-login-provider-gem-oidc-hardening.md`)**:

- Google: `omniauth-google-oauth2` 1.2.2 decodes the ID token without JWKS signature verification.
  `sub` from `extra.id_info` cannot be fully trusted until a local verifier wraps the gem.
- Apple: `omniauth-apple` 1.4.0 enforces nonce only when the returned ID token advertises nonce
  support; local nonce enforcement must be added.
- Neither gem enforces `iat` / `auth_time` freshness against the application's desired maximum
  assertion age.

### 5. WebAuthn RP ID

RP ID is a **domain-level fixed contract**. A passkey registered under RP ID `sign.umaxica.app`
cannot be authenticated against RP ID `umaxica.app` or any other value. Migration is not possible
without re-enrollment.

Current configuration (`config/initializers/webauthn.rb`,
`app/controllers/concerns/sign_webauthn.rb`):

- Per-surface env vars: `WEBAUTHN_{APP|COM|ORG}_RP_ID`
- Common fallback: `WEBAUTHN_RP_ID`
- Startup validation: `Webauthn.validate_rp_id_configuration!`
- Production: request-time fallback to `request.host` is disabled

**Open decision (must be an ADR)**:

| Option      | RP ID                        | Cross-surface passkey           | Surface isolation                |
| ----------- | ---------------------------- | ------------------------------- | -------------------------------- |
| Shared      | `umaxica.app`                | ✅ one passkey for all surfaces | ❌ passkey usable on any surface |
| Per-surface | `sign.app.umaxica.app`, etc. | ❌ re-enroll per surface        | ✅ strict boundary               |

This decision cannot be deferred past the first production passkey enrollment. An ADR is required
before passkeys go live.

### 6. Session / Auth Cookie Host Binding

`__Host-` prefix binds cookies to the exact host, HTTPS, `Path=/`, no `Domain` attribute. Changing
the host terminates all active sessions; there is no migration path.

| Cookie name (production) | Purpose             | Config file                                |
| ------------------------ | ------------------- | ------------------------------------------ |
| `__Host-session`         | Rails session       | `lib/jit_session_cookie_config.rb`         |
| `__Host-auth_access`     | Bearer access token | `app/controllers/concerns/auth_io_keys.rb` |
| `__Host-auth_refresh`    | Refresh token       | same                                       |
| `__Host-auth_dbsc`       | DBSC binding        | same                                       |

All carry `Secure`, `HttpOnly`, `SameSite: Lax`, and `Partitioned` (CHIPS) in production.

**Guardrail needed**: CI assertion that `AuthenticationCookieName.access/refresh/dbsc` produce
`__Host-` prefixed names when `JitSessionCookieConfig.force_secure?` is true.

## P1 Important, Often Forgotten

### 7. Native App Deep Links (Palm)

Android App Links: per-hostname `/.well-known/assetlinks.json` — must be served by the host in the
`app-android-rp` redirect URI. iOS Universal Links: `/.well-known/apple-app-site-association` —
similarly host-scoped.

Current state: `app-ios-rp` and `app-android-rp` use custom URI schemes (`umaxica://`,
`com.umaxica.app:/`). Custom schemes do not require a well-known file but are weaker (no OS
validation). When Universal Links are adopted, the well-known files become a fixed contract.

**Action**: Before switching to Universal Links, register the host and plan the well-known files as
P0.

---

### 8. Cloudflare Turnstile

Turnstile sitekey is bound to an allowed-hostname list in the Cloudflare dashboard. Environment and
surface (app vs com vs org) must be separated. A routing change that moves a form to a different
host requires a dashboard update before the widget will render.

---

### 9. Webhooks

Stripe (and any future: GitHub, Cloudflare, mailer, audit sink) registers endpoint URL + signing
secret per environment. The signing secret is unique per endpoint; path changes require dashboard
update and secret rotation. Raw body verification must be in place before the signature check.

---

### 10. Email Links

Email verification, magic link, password reset, security alert, and unsubscribe URLs are delivered
in messages that users may act on days after receipt.

Rules:

- Route aliases for renamed paths must survive for at least the token TTL after the rename goes
  live.
- Unsubscribe URLs are effectively permanent (users bookmark them; compliance requires they keep
  working).
- Magic link and password reset TTLs: verify before any route rename that old aliases are in place.

---

### 11. CORS / CSRF Trusted Origins / CSP

`trusted_origins`, CORS `Access-Control-Allow-Origin`, and CSP `connect-src` / `form-action` /
`frame-ancestors` are scheme+host contracts. Adding a host for routing convenience without updating
these lists causes CSRF rejection or CSP violations.

Current social auth origin allowlist is in `SocialCallbackGuard` as a hard-coded constant array
keyed on surface env vars. Any new surface host must be added there.

---

### 12. robots / sitemap / canonical / asset host

Less security-critical but affects SEO and CDN caching. If the `com` surface HTML is served from a
Next.js origin, canonical URLs must point to that origin, not to Rails. Do not mix `com` canonical
authority between Rails and Next.js without explicit redirect wiring.
